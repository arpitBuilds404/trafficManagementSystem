# Smart Traffic Management System – Gurugram (DEMO mode)

React + Leaflet/OpenStreetMap frontend, FastAPI backend, trained forecasting model. No API keys needed.

## Run (Windows)
Install Python 3.10+ (tick "Add to PATH") and Node.js 18+ LTS, then double-click **start-all.bat**
(or run `start-backend.bat` and `start-frontend.bat` in two windows). Open http://localhost:5173.

Manual:
    cd backend  && python -m venv venv && venv\Scripts\activate && pip install -r requirements.txt && uvicorn main:app --reload --port 8000
    cd frontend && npm install && npm run dev
API docs: http://localhost:8000/docs

## What is real and what is demo
- **Demo (simulated):** the traffic readings. They are generated by a simulator and replayed on a demo clock that runs
  15x faster than real time (5 demo minutes = about 20 seconds). The UI shows DEMO MODE everywhere.
- **Real:** the forecasting model (ridge regression, direct 6-step forecast: +5, +10, +15, +20, +25, +30 min).
  Inputs: the last six 5-minute speed readings of each segment, time of day, typical demand of the segment.
  It is trained at first start on 21 days of synthetic history (17 train / 4 test) and saved as `backend/model.npz`.
  On the 4 held-out days its error at +30 min is about 2.9 km/h against 3.8 km/h for "assume no change".
- **Not available:** database and Neo4j (not configured; shown as Unavailable on System Status), vehicle counts.
- To use real data: replace `demo_data.generate` / the simulator in `engine.py` with sensor readings and retrain with `ml.train`.

## Pages
Overview · Traffic Monitoring (map, search, filters) · Prediction (30-min forecast, chart, timeline, checks against what
happened, model accuracy) · Alerts & Incidents (filters, acknowledge, report/clear incidents) · Analytics (demo history) ·
Route Planner (now / +15 / +30 min) · System Status (backend, database, Neo4j, model, WebSocket, last update, controls).

## API
GET /api/dashboard · /api/prediction · /api/analytics · /api/status · /api/route?src=RC&dst=CC&horizon=30
GET /api/alerts · POST /api/alerts/{id}/ack · GET/POST /api/incidents · DELETE /api/incidents/{id}
GET/PUT /api/settings (sensitivity, sim_hour) · POST /api/reset · WebSocket /ws (dashboard pushed every 2 s)

## Deploy (Render, one service for backend + frontend)
1. Push this folder to GitHub (the `Dockerfile` must be in the repository root, next to `backend/` and `frontend/`).
2. Render -> New -> Web Service -> choose the repo -> Language/Runtime: **Docker** -> Create.
   (Or New -> Blueprint, which reads `render.yaml`.) Do not create a separate Static Site.
3. Open the `.onrender.com` link. The free plan sleeps when idle: the first visit takes 30-60 s.
Check: `/api/health` returns {"status":"ok"}; `/docs` shows the API.
